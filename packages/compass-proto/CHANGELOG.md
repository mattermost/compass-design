# Changelog

All notable changes to `@mattermost/compass-proto` are documented here.

`compass-proto` is unpublished (`private: true`) prototyping UI, so there are no releases or version sections: entries stay under `[Unreleased]`, each prefixed with the date it landed on `main` (`YYYY-MM-DD`, newest first). Changes to the published `@mattermost/compass-ui` package belong in [its changelog](../compass-ui/CHANGELOG.md), not here.

Format follows [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Added

- **2026-11-16 · `MessageAttachment`:** the card an integration posts under a message (Mattermost / Slack attachment format): color bar (`good`, `warning`, `danger`, `info` or any CSS color), optional title (can link), text, `fields` (short ones sit side by side, stacking below ~440px of the card's own width), image and thumbnail, link or button `actions`, and footer, plus a `pretext` line above the card. Presentational; the host owns what actions do. Field and text values render as plain text, not Markdown. Documented under Patterns.
- **2026-11-16 · `CallCard`:** the call post card, brought over from the proto playground's video-calls prototype. States `calling`, `active`, `joined` and `ended` (Join call, Leave, Cancel, duration and recordings, or a `trailing` slot such as "Call back"); stacks below ~480px of its own width. Presentational: the host owns call state and the handlers, and every label is a prop. Documented under Patterns.
- **2026-11-17 · Composed channel views from the sample workspace (docs):** the Channel, Channel (thread), Channel (channel info), Modal, Call (widget), Product and Threads View layouts, the Call (popout) and Admin Console layouts' people, and the Channels Sidebar pattern now render the sample workspace fixtures instead of hand-written content. A shared `FixtureChannelView` (teams, sidebar, header, bookmarks bar, banner, messages, and a Channel Info or Thread panel that opens from a thread's replies) and `useFixtureWorkspace` back the channel layouts; Threads View lists the real threads (followed, or with an unread mention), and call participants come from the channel's members. Supporting changes: posts carry `createdAt` (ISO 8601, for ordering across channels), `buildChannelsSidebarModelFromFixtures` takes `showUnreadsCategory` (an Unreads group of channels with badges), and `RightSidebarThread` no longer reuses a React key for two replies by the same person in the same minute.
- **2026-11-17 · `MessageAttachment` thumbnail column:** `thumbSrc` now fills a 140 by 140 column on the right, beside all the content (it was a 40px image in the title row), cropped to fill with 2px corners. New `thumbnail` slot puts your own content in the same box (it wins over `thumbSrc`). Below roughly 440px of the card's own width the column moves below the content. Fixture attachments with a `thumbUrl` (the MissionOps weather alerts) use it.
- **2026-11-17 · Teams in the sample workspace fixtures:** the generated fixtures now cover every team the login persona is on (Cyber Defense HQ, DevSecOps HQ, MissionOps HQ): `cyberDefenseTeams` (id, name, initials, and the persona's unread / mention badge per team) alongside `cyberDefenseTeam` (the first). Channel ids are now `team/channel`, `FixtureChannel.teamId` is optional (direct and group messages belong to no team), and `buildChannelsSidebarModelFromFixtures` takes `teamId`. `ChannelShell` takes `onSelectTeam`, forwarded to the Team Sidebar. New post kind `run-reminder` (Playbooks status-update and retrospective reminders, with their button in `attachments`), new emoji and integration icons, and the generator saves icons under their real file type (PNG, JPEG or WebP) and copies the team icons. The Channel layout switches between the teams.
- **2026-11-17 · `ChannelBanner`:** the strip across the top of a channel, following the Mattermost webapp's channel banner: a 24px full-width bar, 2px by 24px padding, one centered 13px line with an ellipsis when it does not fit, and links underlined in the text color. `backgroundColor` sets the color and the text turns black or white to contrast with it (`channelBannerTextColor`, the webapp's luminance rule; `textColor` overrides). When the text is cut off, hovering shows the full text in a `WithTooltip` (`tooltip`, or `children` when it is a string). Renders nothing without text. `textAriaLabel` optionally names the text (unset by default, so screen readers read the copy). Documented under Patterns; the Channel layout uses it for a channel's banner. `WithTooltip` takes an optional `className` for its wrapper.
- **2026-11-17 · Channel layout: bottom-anchored message lists and webapp Markdown styling (docs):** the Channel layout and the other desktop and mobile channel specimens open on the newest message and stay anchored to the bottom while content grows, until the reader scrolls up (`useStickToBottom` in the docs app's `src/hooks`). The docs Markdown renderer for sample posts follows the webapp's text formatting (heading scale, list and paragraph spacing, quotes, code blocks, inline code, tables, rules, strikethrough), using Compass font-size, line-height, font-weight, font-family, spacing and opacity tokens in place of the webapp's literals. The margins on the text's outer edges (above its first block, below its last) are dropped, so they don't add to the spacing the message layout puts between a post's parts; spacing between blocks inside the text is kept. Call posts show "Call ended" once, in the call card, instead of repeating it above the card; the "Edited" marker (a small pencil and the word) sits inline at the end of the post text, on its own line only when the text ends in a list, code or table, and is left off posts a card speaks for.
- **2026-11-17 · Team sidebars, Mobile Channel Sidebar, Channel Header and Message specimens from the sample workspace (docs):** the Team Sidebar and Mobile Team Sidebar show the workspace's teams and switch the active one on click; the Mobile Channel Sidebar builds its model from the fixtures; the Channel Header variants (channel, favorited and muted, bot, DM, GM, Threads, Drafts) and the Message specimen use real channels and posts, with the state matrix kept explicit.
- **2026-11-17 · Quick Switch Modal, Search Modal, Right Sidebar, Profile Popover and Call Card specimens from the sample workspace (docs):** the switcher and the search dialog list the signed-in user's real channels, direct messages, people, files and teams (message results search the workspace's posts); the Right Sidebar shows a real thread, channel info, members and search results; the Profile Popover shows real people (the popover's local time, last online and badges are still written in the specimen, as the sample data has none); the Call Card uses a channel's members and a real call's duration. Variant and state matrices stay explicit.
- **2026-11-17 · `ChannelShell` inner panel outline:** the panel's left border is now a 1px outline in the same color, so it follows the rounded corners and takes no space (also applies to `ProductShell`).
- **2026-11-17 · `Message` `priority` and `priorityLabels`:** `priority="urgent" | "important"` shows a label in the message header, right after the timestamp (danger color for urgent, info color for important), instead of above the body. `priorityLabels` overrides the text (defaults "Urgent" / "Important"). The published `MessageHeader` is unchanged: `Message` passes the label through its `timestamp` slot.
- **2026-11-16 · `buildChannelsSidebarModelFromFixtures` and `RightSidebarChannelInfo` props:** `buildChannelsSidebarModelFromFixtures({ channels, users, currentUserId, activeChannelId, avatars, threadsMentionCount, onSelectChannel })` builds the channels sidebar from fixture channels: Favorites, Channels, then Direct Messages (direct and group) with the other person's avatar and custom status, unread / mention badges from `unreadCount` / `mentionCount`, a Threads row badge, only channels the current user belongs to, and no empty groups. `RightSidebarChannelInfo` now takes `name`, `purpose`, `header`, `channelId`, `favorited`, `muted`, `showAddPeople`, `memberCount`, `pinnedCount` and `fileCount` (`purpose`, `header` and `channelId` accept `null` to hide their section); with no props it renders the same demo content as before. `attachmentFileType`, `attachmentMeta`, `fileExtension` and `formatFileSize` are exported from the root barrel. The Channel layout in the docs now renders the Cyber Defense HQ fixtures: sidebar, header, bookmarks bar, banner, messages and Channel Info.
- **2026-11-16 · Cyber Defense HQ fixtures:** exports `cyberDefenseUsers` (people and bots; ids are usernames), `cyberDefenseTeam`, `cyberDefenseCurrentUserId`, `cyberDefenseChannels`, `cyberDefensePosts` and `cyberDefenseThreads`, with `getCyberDefenseUser` / `Channel` / `Post` / `ChannelPosts` lookups. The data is **generated** from the `trial-journey` dataset in `mattermost/mattermost-preview` by `npm run generate:cyber-defense-fixtures -- --source <path>`: repeatable, and it stops with a clear message on anything it doesn't map (see the README next to `generated.ts`). Channels are the team's channels plus the direct and group messages the login persona has open, with the persona's `favorite`, `unreadCount`, `mentionCount`, `firstUnreadPostId`, `pinnedCount` and `bookmarks`. Posts are the sample workspace's messages verbatim, without join/leave/add system posts, and carry what a host needs to render them: `kind` (`webhook`, `slack-attachment`, `run-update`, `call`, `bot-reply`), `reactions`, `priority` / `requestAck` / `acknowledgements`, `edited`, `pinned`, `followerIds`, `files`, Slack-style `attachments`, `webhook` identity (`iconId`), `permalinkPostId`, `runUpdate` and `call`. Reaction and custom-status emoji are glyphs (the closest standard emoji replace `thank-you` and the `large_*_circle` names). Presence: people who post are `online`, the rest rotate through away, do-not-disturb and offline. Fixture types gained the matching optional fields. `createAvatarRegistry` now also matches files named after a user id or username (`areid.png`). The docs app holds the images: `src/assets/avatars/<username>.png` and `src/assets/integrations/*.png` (brand icons used by the alert posts), with `src/fixtures/integrationIcons.ts` mapping `iconId` to the image.
- **2026-11-15 · `SearchModal` (universal search):** the dialog behind the global header's Search field, ported from the Universal Search prototype. A `SegmentedControl` of modes (All, Channels, Messages, Files, People, Agents) sits where the title would be, over a large `SearchInput` and one `role="listbox"` (built on `SuggestionList`) whose content changes with the mode and the query: before-typing and typing states per mode, recent searches with a pointer remove control and Shift+Delete, `from:` people suggestions that become modifier chips, modifier tip buttons, "Enter to search", an Agents footer with a "Search with" picker, a People footer, a Channels browse link, a no-results empty state (People shows "People you chat with most" as a row of person cards that join the same keyboard list), Agents lists recent questions (`recentAgentSearches`, removable) and suggested questions (`agentSuggestions`, narrowed while typing) with the first highlighted, a sparkle on its tab, a `defaultAgentId` for the footer picker (default: the first agent), and "Search by topic or ask AI a question" as the placeholder (with nothing to list, the body is dropped); and an optional team selector (`teams`, `teamId`, `onTeamChange`). It has no visible title or close button and hangs from the Search field (`anchor`: 8px below its top edge, centered, over a transparent scrim that still closes on click). Host-owned: `open`, `data`, `onSelect` (`{ kind, item }`, plus `agentId` for a question chosen in Agents mode), `onSubmit` (`{ mode, query, chips, agentId }`), `onRemoveRecent`, `onModeChange`, plus `initialMode`, `modes`, `overlayProps`, `manageFocus` (turn off for an always-open staged preview) and a translatable `labels` object. A quick close and reopen starts fresh instead of keeping the old mode and text. All, Channels, Files and People open the first row on Enter; Messages searches on Enter and highlights nothing until an arrow key; Agents opens the highlighted suggestion and sends a question that matches none. Switching mode slides the results in (from the right for a later mode, the left for an earlier one; off under `prefers-reduced-motion`). `GlobalHeader` is unchanged. Documented on its own Search Modal pattern page. Part of #272, #386.
- **2026-11-15 · `Message` and `MessageInput` pass-through props:** `Message` (now exported as `MessageProps`) accepts HTML attributes (`data-*`, `aria-*`, `id`, handlers such as `onClick`) on its root, forwards a `ref` to the root, takes an `avatar` slot that replaces the default `UserAvatar`, and widens `username` to `ReactNode`. `MessageInput` accepts HTML attributes on its root, `onSend(value)` (Send button, and Enter without Shift when `onSend` is set; skipped for empty text, IME composition and Enter the host already prevented) and a `suggestions` slot above the input box, and `textareaProps` for the text area (e.g. `useSuggestionList`'s `inputProps` and `onKeyDown` for combobox semantics). Default markup and behavior are unchanged when the new props are unset.
- **2026-11-15 · `getTextareaCharRect`:** measures where a character sits inside a textarea, in viewport coordinates (hidden mirror with the same wrapping, follows the textarea's scroll), so a popup can be placed at a trigger character such as `@`. It is the anchor for the Suggestion List specimen, together with compass-ui's `useAnchoredPopupPortal` (virtual anchor, `side="above"`). Part of #258.
- **2026-11-15 · `RightSidebarSearchResults`, `SearchResultMessage` and `SearchHighlight`:** one RHS body for search results, mentions, saved and pinned messages. Each result is a context line (channel, muted team) above the existing `Message`, whose hover toolbar is the `search-results` Message Actions with its Jump button wired to `onJump` (Pinned + Saved row when `pinned`/`saved`), with a string body highlighted for `terms` using `<mark>` and the theme's mention-highlight colors. `RightSidebarSearchResults` adds a count line (`countLabel`) and a per-`kind` empty state with its own illustration (`message-search-empty`, `mentions-empty`, `saved-empty`, `pinned-empty`; `emptyTitle` / `emptyDescription` override it); labels have English defaults (`jumpLabel`, `jumpAriaLabel`, `listLabel`). `splitSearchHighlight` is exported for hosts that render their own body. `Message` gains `messageActionsProps` (forwarded to its hover toolbar). `RightSidebar` `alignBody` gains `'stretch'` (content takes the body's height, taller content still scrolls) so the empty state centers vertically; pair the panel with it. Documented in the Right Sidebar pattern (guideline and specimen). Files results and the search-box/tabs chrome are not included yet. Part of #264.
- **2026-11-15 · Attach a file opens the OS dialog first; `ChannelBookmarkModal` shows an attachment card:** new `pickBookmarkFile()` opens the file dialog (call it from the "Attach a file" click) and the modal takes the picked `file`, `uploadProgress` (uploading state; submit disabled below 100) and `onFileChange` (card Edit replaces the file, close removes it). The title follows the file name until edited. The empty "Choose file" button remains for a modal opened without a file.
- **2026-11-15 · `ChannelHeaderMenu` `bookmarksBarActive`:** shows the static "Bookmarks bar" row in its active state, for previews of the open submenu.
- **2026-11-15 · `ChannelBookmarkModal` `overlayStyle` and `manageFocus`:** `overlayStyle` styles the scrim (pair with `container` and `position: 'absolute'` to stage the modal in a frame); `manageFocus` (default `true`) turns off initial focus, trap and restore for static docs previews.
- **2026-11-15 · `ChannelBookmarksBar` `onReorder` (drag-to-reorder):** visible bookmarks can be reordered by dragging one onto another, with a drop marker and a dimmed source, or with Alt + Arrow Left / Right on a focused bookmark (announced through a live region; new `labels.reordered`). Only active when `canManage` and `onReorder` is set. Called with the full list in its new order. New helpers `moveItem` / `dropIndex` are covered by tests.
- **2026-11-15 · `ChannelHeaderMenu` `onAddBookmark` (Bookmarks bar submenu):** with `onAddBookmark` set, the "Bookmarks bar" row opens a submenu beside it with "Add a link" and "Attach a file" (as in the webapp) and calls `onAddBookmark('link' | 'file')`. Opens on hover, click, or Right Arrow; Left Arrow / Escape closes just the submenu. The submenu is portaled and its layer carries `data-popover-submenu` so a host's outside-press check can treat it as part of the menu. Without the prop the row is unchanged. The Channel layout specimen opens the menu from the channel name and its choices open the add modal.
- **2026-11-15 · Product Rail unread dots use `UnreadBadge`; team menu rows use `MenuItem`:** the dots on rail tiles and the team button, and the unread dot in the team menu, are now compass `UnreadBadge`s (decorative where the control's accessible name already carries the status; labelled via `unreadLabel` in the menu). Team menu rows moved from custom buttons to `MenuItem` (`role="menuitemradio"`, `aria-checked`); the unread dot is centred in a check-sized box so it lines up with the check. `ProductRailTeam.urgent` is removed because `MenuItem`'s mention count has no urgent style. - **2026-11-15 · `ClipboardTextOutlineIcon`, `BullseyeArrowIcon`, `MessageProcessingOutlineIcon` and `BookOpenVariantOutlineIcon`:** local icons for Playbooks, Boards, Channels and Docs (Boards and Playbooks use the adjusted lighter drawings from design) (the Channels one is a speech bubble with three round dots), since `@mattermost/compass-icons` does not ship them. ### Changed

- **2026-11-15 · `ChannelHeaderMenu` Bookmarks bar submenu motion:** the submenu slides 8px toward the side it opens to while fading in, and plays the same motion in reverse on close (it stays mounted through the exit), per the Popover Menu guideline.
- **2026-11-15 · Bookmark default icons:** links show a book icon and attachments a file icon (as in the webapp) when no emoji is set — in `ChannelBookmarksBar` items and in the `ChannelBookmarkModal` emoji button (previously a link icon and a smiley).
- **2026-11-15 · `ChannelHeaderMenu` Bookmarks bar submenu geometry:** the submenu overlaps its parent by 8px and its first item aligns with the row (the submenu recipe), instead of sitting 4px beside it.

- **2026-11-15 · `ChannelBookmarksBar` overflow and add are one control (matching the webapp):** when bookmarks overflow, the separate `+N` chip and plus button are replaced by a single plus button with the hidden count (`IconButton` `count`; a more icon when `canManage` is false). - **2026-11-15 · `GlobalHeader` `showProductBranding`; `ProductShell` hides the header product name:** new `showProductBranding` prop (default `true`, so existing uses are unchanged) hides the product icon and name for any product. `ProductShell` sets it to `false` because the Product Rail already shows the active product; pass `globalHeaderProps={{ showProductBranding: true }}` to restore it. Part of #273.
- **2026-11-14 · `GlobalHeader` `product` accepts `'agents'`, `'docs'`, `'automation'`:** adds branding (sparkle `creation-outline`, `book-outline`, `lightning-bolt-outline` icons) for the new Product Rail products. Existing values are unchanged. Part of #273.
- **2026-11-12 · `MobileMessageInput` `variant` values are now lowercase kebab-case (breaking for hosts that passed the old values):** `variant` takes `'root'` and `'reply'` instead of `'Root'` and `'Reply'`, matching the public variant-value convention. Update any `variant="Root"` / `variant="Reply"` usage to the lowercase values; the default is still `'root'`. Nothing else in the component's API changes.
