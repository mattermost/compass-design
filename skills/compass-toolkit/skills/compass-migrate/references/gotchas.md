# Gotchas, by compass-ui version

Each row says where it comes from and which versions it applies to. **Verified** means I checked it against the compass-ui source at alpha.29, or against the release commit named in the row. **Seen** means a reference migration did it (gcal = mattermost-plugin-google-calendar PR 179, alpha.22; dataminr, alpha.22; agents, alpha.23). **Reported** means consumer feedback that I could not reproduce here: treat it as a lead, confirm it, and don't state it to the user as fact.

Before relying on any row, read the installed compass-ui version and the `CHANGELOG.md` entry for the release that matches. If a row's fix has shipped, follow the new behavior and drop the workaround.

| # | Gotcha | Applies to | What to do | Status |
| --- | --- | --- | --- | --- |
| 1 | **Combobox opens on click or typing, not on focus.** Tests or flows that focus the field and press Enter find the menu closed. | Default at every version I checked; the `openOnFocus` opt-in arrived in alpha.24 (changelog) | Click the field, or type, before asserting options. If a flow really needs open-on-focus (a popover search with `autoFocus`), pass `openOnFocus` (opt-in, default `false`). Report the change for any flow that relied on it. | Verified |
| 2 | **Menus render behind modals or outside the stacking order.** At alpha.28 and earlier, `--z-modal` is 200, `--z-tooltip` 300, there is no `--z-menu`, and portaled menus (`Select`, `Combobox`, `DateRangePicker`) default to a hardcoded 1000. A modal raised to the webapp's layer (1050) therefore covers its own menus. | alpha.28 and earlier. Fixed in alpha.29 (#218): `--z-modal` 1050, `--z-menu` 1100, `--z-popover` 1200, `--z-tooltip` 1350; menus default to `var(--z-menu, 1100)`. | On alpha.28 and earlier: pass `zIndex` to `ModalOverlay`, `Select`, `Combobox` and `DateRangePicker` from one constants file (team convention: modal 1050, confirm modal 1060, menu portals 1070). On alpha.29 and later: delete those props and the constants and use the tokens; keep only a number for a confirm dialog opened over another modal (no token sits between modal and menu), and re-check each modal in the browser. Other plugins used 1000/1060 (gcal) and 2000/2100 (agents), so unify them in the migration. | Verified: alpha.28 values at commit `5154e93`, alpha.29 values at release commit `b80d526`. The 1050/1060/1070 numbers are a convention, not a Compass token. |
| 3 | **Async select breaks without all four parts.** | alpha.11 and later (`selectedOptions`, `loading`) | `filter={false}`, a request-id guard against stale responses, `selectedOptions` backed by a cache of every label loaded, and `zIndex`. In a multi-select, hide already-selected values from `options`, because re-selecting a committed value toggles it off. Full code in `patterns.md`. | Seen (gcal) |
| 4 | **Enter in an open Combobox with nothing to pick** used to submit the surrounding form. | Fixed in alpha.26 | On older versions, expect a form submit and guard it. On alpha.26 and later it is handled and stops propagating; tests that relied on the submit need updating. | Verified |
| 5 | **Stacked modals: Escape and focus.** Two open modals from different compass-ui copies both handled Escape and Tab. | Fixed in alpha.19 | Require alpha.19 or later when a plugin opens a confirm over a modal. A confirm over a modal closes alone on Escape. | Verified |
| 6 | **Dialog locators match more than one dialog** when modals are stacked. | Any | `Modal` renders `role="dialog"` with `aria-modal="true"` and `aria-labelledby` its title. Nothing sets `aria-hidden` or `inert` on a lower modal: the modal stack only makes lower modals ignore Tab and Escape. So both dialogs are visible to `getByRole('dialog')`. In Playwright use `getByRole('dialog', {name: '...', exact: true})`, and give each dialog a specific title. | Verified (source) |
| 7 | **Webpack has no rule for compass-ui's `.css`**, or a combined `scss\|css` rule runs sass on it. | Any | Split into a `.css` rule (`style-loader`, `css-loader`) and an `.scss` rule. See `infra.md`. | Seen (gcal) |
| 8 | **`simplebar-react` is a required peer dependency.** | Required from alpha.13 | Add it explicitly. npm 7+ installs it; other package managers may not. | Verified |
| 9 | **A footer submit button doesn't submit the form** because it is outside the `<form>`. | Any | `type='submit'` and `form={FORM_ID}` on the button, `id={FORM_ID}` on the form. | Seen (gcal) |
| 10 | **Icons.** Raw glyphs, wrong import path, or an explicit `size` on slotted icons. | Any | Import from `@mattermost/compass-icons/components` and wrap: `<Icon glyph={<XIcon/>}/>`. Icon-only buttons are `IconButton` with an `aria-label`. | Seen (gcal) |
| 11 | **Leftover theme code.** Agents keep the old theme-prop architecture and react-select style overrides unless told to delete them. | Any | Rule 3 of the skill. Delete them in the same change, and say so in the report. | Reported (and a skill rule) |
| 12 | **Strict TypeScript variance errors on `onChange` props.** `Select` and `Combobox` declare `onChange` as a property-style function type (`onChange?: (value: string) => void`), which `strictFunctionTypes` checks contravariantly. A handler typed with a narrower parameter, such as `(v: 'a' \| 'b') => void`, is rejected; a method-style declaration (`onChange?(value: string): void`) would accept it. | Any version with property-style props (alpha.29) | Type the handler parameter as the declared type (`string`, or `string \| string[] \| null` for `Combobox`) and narrow inside, instead of casting. Report it as a library issue if it blocks you; the fix is method-style signatures in compass-ui. | Verified (reproduced with `tsc --strict`; declarations read at alpha.29) |
| 13 | **jsdom's `getComputedStyle` throws on pseudo-elements.** | Not reproduced | If a test fails this way, stub it for the test file. Don't change the component. | Reported |
| 14 | **ESLint flags compass-ui subpath imports.** | Not reproduced | Ignore the subpaths in the unresolved-import rule. Don't switch to the root barrel. | Reported |
| 15 | **No required marker, and `required` means different things.** Compass draws no visible marker. `TextInput` and `TextArea` pass `required` to the native input (browser validation can run on submit); `Select` and `Combobox` set `aria-required` only. | Any | Add the star in the label (`patterns.md`, pattern 2), `aria-hidden`, and keep your own validation. | Verified (source) |
| 16 | **Field errors drawn as a separate `ErrorMessage`.** | Any | Use the field's own `message` (error tone by default) on `Select`, `Combobox`, `TextInput`, `TextArea`. `ErrorMessage` is `FieldMessage` in the error tone, kept for existing imports; use it only where the input has no `message` prop (`DateRangePicker`). | Verified (source) |

## When a gotcha isn't listed

Check the `CHANGELOG.md` for the installed version and the one after it. If the behavior you hit looks like a Compass defect, report it in section 4 of the report rather than working around it silently.
