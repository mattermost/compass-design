Search Inputs are the entry point to filtering or finding content — global
search, channel switcher, member picker, file finder. They look like a
text input with a leading magnifier so the affordance is obvious before the
user reads a single word.

Reach for a Search Input whenever the field's job is "find something" rather
than "enter a value." Use a [Text Input](/components/text-input)
for free-form data entry instead.

## Anatomy

<AnatomyStage style={{ flexDirection: 'column', gap: '0.75rem' }}>
  <div style={{ width: '100%', maxWidth: '320px' }}>
    <SearchInput placeholder="Search messages" />
  </div>

- <Num>1</Num> **Leading icon** — a magnifier. Always present; signals the
  field's purpose.
- <Num>2</Num> **Input** — the editable field. Accepts a placeholder or a
  floating label.
- <Num>3</Num> **Clear button** — appears once the field has a non-empty value
  and is not disabled. Built-in clearing works when `onClear` is omitted.
  Removed from the tab order by default (`tabIndex={-1}`).

| Size   | Use when                                                             |
| ------ | -------------------------------------------------------------------- |
| Small  | Compact toolbars, inline filters, side panels.                       |
| Medium | The default. Forms, modals, channel and DM finders.                  |
| Large  | Hero placement — a dedicated search page or a top-of-channel finder. |

## States

States mirror the rest of the input family: Default, Focus (a blue ring on
the border), Filled (the floating label settles above the input), and
Disabled.

<div
  style={{
    display: 'flex',
    flexDirection: 'column',
    gap: '0.75rem',
    padding: '1rem 0',
    maxWidth: '320px',
  }}
>
  <SearchInput label="Search" placeholder="Default" />
  <SearchInput label="Search" defaultValue="design system" onClear={() => {}} />
  <SearchInput label="Search" placeholder="Disabled" disabled />
</div>

A clear button appears once the field has a value. Pass `onClear` when the
host owns the value; omit it to use built-in clearing (uncontrolled state or
a synthetic change for controlled inputs). Escape clears when the button
would be visible.

## Status message

Pass `message` / `messageTone` the same way as Text Input. Error tone (the
default) adds invalid chrome; info does not.

<div
  style={{
    display: 'flex',
    flexDirection: 'column',
    gap: '0.75rem',
    padding: '1rem 0',
    maxWidth: '320px',
  }}
>
  <SearchInput label="Search" message="No matches found." />
  <SearchInput
    label="Search"
    defaultValue="design"
    message="Try another keyword."
    messageTone="info"
  />
</div>

Search Input does not take `trailingAction` — its trailing control is the
clear button.
