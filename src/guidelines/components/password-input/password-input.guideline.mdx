Password Inputs are the dedicated field for secrets — login, signup, invite
passwords. They look like a text input with a built-in show/hide toggle so the
affordance is obvious before the user reads a single word.

Reach for a Password Input whenever the field's job is "enter a secret." Use a
[Text Input](/components/text-input) for free-form data entry, or a
[Search Input](/components/search-input) when the job is "find something."

- <Num>1</Num> **Input** — the editable field (`type="password"` until
  revealed). Accepts a placeholder or a floating label.
- <Num>2</Num> **Reveal toggle** — always present; switches between show and
  hide. Sized from the field `size`. Override the accessible names with
  `showPasswordLabel` / `hidePasswordLabel`.

| Size   | Use when                                          |
| ------ | ------------------------------------------------- |
| Small  | Compact toolbars, dense settings rows.            |
| Medium | The default. Login, signup, modals.               |
| Large  | Setup flows, mobile-leaning surfaces, hero forms. |

## States

States mirror the rest of the input family: Default, Focus, Filled, Revealed,
and Disabled. When disabled, the value stays masked even if it was revealed.

<div
  style={{

  <PasswordInput label="Password" defaultValue="secret-value" disabled />
</div>

## Field message

Pass `message` / `messageTone` the same way as Text Input and Search Input.
Error tone (the default) adds invalid chrome; info does not.

<div
  style={{
    display: 'flex',
    flexDirection: 'column',
    gap: '0.75rem',
    padding: '1rem 0',
    maxWidth: '320px',
  }}
>
  <PasswordInput
    label="Password"
    message="Use 8 or more characters."
    messageTone="info"
  />
  <PasswordInput
    label="Password"
    defaultValue="wrong"
    message="Password is incorrect."
  />
</div>

Password Input does not take `clearable` or `trailingAction` — its trailing
control is the reveal toggle.
