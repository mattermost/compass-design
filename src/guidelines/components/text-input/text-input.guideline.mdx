Text Inputs let people enter and edit a single line of text — names, emails,
search queries, channel titles. They're the workhorse of every form and
modal in Mattermost. For passwords with show/hide, use
[Password Input](/components/password-input).

## Anatomy

<AnatomyStage>
  <div style={{ width: '100%', maxWidth: '420px' }}>
    <TextInput
      label="Search"
      defaultValue="design"
      clearable
      leadingIcon={<Icon glyph={<MagnifyIcon />} />}
    />
  </div>
</AnatomyStage>

- <Num>1</Num> **Container** — rounded border with a 1px stroke.
- <Num>2</Num> **Label** — floating label that sits inside the field at rest and
  lifts above the border on focus or when the field has a value.
- <Num>3</Num> **Leading icon** — optional; reinforces the field's purpose
  (search, mail, calendar).
- <Num>4</Num> **Trailing control** — in-field clear (`clearable`) or, for
  secrets, the show/hide eye on [Password Input](/components/password-input).
  Don’t combine clear with password reveal. Outside-the-field actions use
  `trailingAction`.
- <Num>5</Num> **Placeholder** — brief sample or help statement; only visible
  when empty.
- <Num>6</Num> **Value** — the text the user has entered.

## Sizes

Pick a size to match the surface, not the content. Don't mix sizes inside the
same form.

| Size   | Use when                                          |
| ------ | ------------------------------------------------- |
| Small  | Compact tables, toolbars, dense settings rows.    |
| Medium | The default for forms and modals.                 |
| Large  | Setup flows, mobile-leaning surfaces, hero forms. |

<div

  <TextInput

  <TextInput size="large" label="Large" placeholder="example@mattermost.com" />
</div>

## States

| State     | Description                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------------- |
| Default   | Resting state.                                                                                                |
| Hover     | Subtle stroke darkening on pointer hover.                                                                     |
| Focus     | Active focus ring. The label floats above the border.                                                         |
| Read-only | Non-editable but visible — e.g. system-derived values the user can't change.                                  |
| Disabled  | Inactive state. The field is non-interactive and visually de-emphasised.                                      |
| Invalid   | Validation has failed. Pass `message` (error tone by default) or set `invalid` alone for chrome without copy. |

<div
  style={{
    display: 'flex',
    flexDirection: 'column',
    gap: '1rem',
    maxWidth: '420px',
  }}
>
  <TextInput label="Default" placeholder="Type here…" />
  <TextInput label="With value" defaultValue="hello@mattermost.com" />
  <TextInput label="Disabled" placeholder="Type here…" disabled />
  <TextInput
    label="Invalid"
    defaultValue="not-an-email"
    message="Enter a valid email address."
  />
</div>

## Field message

Pass a host-computed `message` under the field. The host owns validation;
Compass only displays what it is given. Default tone is error (invalid ring
and `role="alert"`). Warning, info, and success show the line without the
error ring.

<div
  style={{
    display: 'flex',
    flexDirection: 'column',
    gap: '1rem',
    maxWidth: '420px',
  }}
>
  <TextInput label="Email" message="This field is required." />
  <TextInput
    label="Channel name"
    message="This name is already taken."
    messageTone="warning"
  />
  <TextInput
    label="Password"
    message="Use 8 or more characters."
    messageTone="info"
  />
  <TextInput
    label="Invite code"
    defaultValue="abc-123"
    message="Looks good."
    messageTone="success"
  />
</div>

For the same line outside a text field (e.g. under a radio group), use
[Field Message](/components/field-message).

## Trailing controls (in-field)

The trailing slot inside the border is for **clear** or **password show/hide**
— not arbitrary decorative glyphs.

- **Clear** — set `clearable` on Text Input. The button stays in the tab order.
  Pass `onClear` when the host owns the value; omit it for built-in clearing.
  Escape clears when the button would be visible.
- **Password show/hide** — use [Password Input](/components/password-input),
  which ships the eye toggle. Don’t hand-roll an eye on Text Input, and don’t
  combine clear with password reveal.

<div
  style={{
    display: 'flex',
    flexDirection: 'column',
    gap: '1rem',
    maxWidth: '420px',
  }}
>
  <TextInput label="Filter" clearable defaultValue="design" />
  <PasswordInput label="Password" defaultValue="secret-value" />
</div>

## Trailing action (outside)

`trailingAction` sits outside the border, beside the field — labeled actions
like Copy. Use a primary `Button` (the default) and match `size` to the field;
the slot stretches to the same height as the Text Input. Message and character
counter stay as wide as the field column, not under the action.

<div style={{ maxWidth: '480px' }}>
  <TextInput
    label="Invite code"
    defaultValue="abc-123"
    message="Copied to clipboard."
    messageTone="success"
    trailingAction={<Button>Copy</Button>}
  />
</div>

<Divider />

## Leading icon

Use a leading icon to reinforce a recognisable input type — magnifier for
search, mail icon for email. Trailing in-field controls are clear or password
reveal (see above); outside-the-field actions use `trailingAction`.

<div style={{ maxWidth: '420px' }}>
  <TextInput
    label="Search"
    placeholder="Search channels"
    leadingIcon={<Icon glyph={<MagnifyIcon />} />}
  />
</div>

<Divider />

## Variants

- **Bordered** — the default. Use anywhere the field needs to read as an
  obvious input target.
- **Borderless** — for product verticals with real-time editing where the
  border would compete visually (inline title editing, quick-edit fields).

<Divider />

## Content

- Labels describe the input as briefly as possible — sentence case, no
  trailing punctuation or colons.
- Use placeholders for hints, not as a substitute for the label.
- Validation messages should be specific and constructive ("Enter a valid
  email", not "Invalid input").
