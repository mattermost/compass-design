Admin Panel Footer is the action rail at the bottom of an
[`Admin Panel`](/patterns/admin-panel). It provides start- and end-edge slots
for `Button`, `IconButton`, or pagination controls — layout and divider chrome
only; the host owns labels and handlers.

<Divider />

## Anatomy

A top divider separates the footer from the panel body. Actions sit on opposite
edges with a flexible gap between them.

- <Num>3</Num> **Right actions** — end-edge slot for primary commit paths,

## Options

| Option        | Use when                                                                                      |
| ------------- | --------------------------------------------------------------------------------------------- |
| Left only     | A single sectional action (add row, filter) belongs on the start edge.                        |
| Right only    | Commit or dismiss actions sit on the end edge without a leading control.                      |
| Both sides    | Pair a leading utility with trailing commit or pagination.                                    |
| Pagination    | Pass status copy or `PaginationDots` in one slot and Previous / Next controls in the other.   |
| Icon buttons  | Dense toolbars — keep accessible names via `aria-label` on each `IconButton`.                 |

<Divider />

## Behaviour

- **Compose, don’t hard-code.** The footer does not own Save / Cancel labels —
  page-level save stays in [`Admin Console Footer`](/components/admin-console-footer).
- **Collapse with the panel.** When used via `AdminPanel`’s `footer` prop on an
  expandable panel, the footer hides with the body.
