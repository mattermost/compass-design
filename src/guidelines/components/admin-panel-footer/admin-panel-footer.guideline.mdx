Admin Panel Footer is the action rail at the bottom of an
[`Admin Panel`](/patterns/admin-panel). Compose it via the panel’s optional
`footer` prop (the panel still needs a header or a body). It provides start-
and end-edge slots
for `Button`, `IconButton`, or pagination controls — layout and divider chrome
only; the host owns labels and handlers.

<Divider />

## Anatomy

A top divider separates the footer from the panel body. Primary actions sit on
the start edge (primary button leftmost when used). A second slot can hold
trailing utilities or pagination on the end edge.

- <Num>3</Num> **Right actions** — optional end-edge slot for secondary
  utilities or pagination icon buttons.

## Options

| Option          | Use when                                                                                       |
| --------------- | ---------------------------------------------------------------------------------------------- |
| Primary actions | A single Save / Cancel (or similar) group — always on the start edge, primary button leftmost. |
| Both sides      | Pair primary actions on the left with a trailing utility or pagination on the right.           |
| Pagination      | Status copy on the left; previous / next as `IconButton`s (or `PaginationDots`) on the right.  |

<Divider />

## Behaviour

- **Primary on the left.** One action group always aligns to the start edge.
  When a primary button is present, place it first in that group.
- **Compose, don’t hard-code.** The footer does not own Save / Cancel labels —
  page-level save stays in [`Admin Console Footer`](/components/admin-console-footer).
- **Collapse with the panel.** When used via `AdminPanel`’s `footer` prop on an
  expandable panel, the footer hides with the body.
