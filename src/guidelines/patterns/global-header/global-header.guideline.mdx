The Global Header is the full-width bar at the very top of the application. It
carries product context, history navigation, global discovery (where the product
allows), and session-level actions — help, settings, and the signed-in account —
so users keep the same muscle memory as they move across surfaces.

It sits above regional chrome such as the Channel Header; together they form the
vertical hierarchy from platform → product → conversation context.

## Anatomy

The layout is grouped into left, optional center (Channels only), and right
clusters. The diagram shows the default Channels configuration.

<GlobalHeaderAnatomyStage />

- <Num>1</Num> **Product switcher** — Opens the grid of Mattermost products.
  Uses an inverted icon button sized for the dense header.
- <Num>2</Num> **Product branding** — Product glyph plus label (Channels,
  Playbooks, or Boards). On Channels, branding can be toggled off with
  `showChannelsBranding={false}` when the switcher alone is enough.
- <Num>3</Num> **Navigator** — Back and Forward affordances for in-app history
  (inverted icon buttons).
- <Num>4</Num> **Global search** — Channels only. Centered search field with
  leading magnifier; opens team / message discovery flows from the shell.
- <Num>5</Num> **Help** — Channels: inverted icon beside search in the center
  cluster. Playbooks and Boards: the same help affordance moves into the right
  cluster when there is no center column.
- <Num>6</Num> **Upgrade** — Optional Primary button (`showUpgradeButton`). Use
  when licensing or upgrade messaging belongs in the global chrome.
- <Num>7</Num> **Product shortcuts** — Channels: Recent mentions and Saved
  messages (inverted icons). Playbooks: Tasks. Boards: no extra shortcut in this
  implementation — the right cluster goes from optional Upgrade to Help, then
  Settings and Account.
- <Num>8</Num> **Settings** — Session settings entry (inverted cog icon).
- <Num>9</Num> **Account menu** — Signed-in avatar with presence; activates the
  account menu. Implemented as a transparent hit target with hover feedback.
  When a custom status is set, its emoji sits in the same control (hover tooltip
  only — status details are in the account menu).

The bar sits on the dark sidebar header background with inverted icon buttons so
controls stay legible. Search and account affordances use short hover transitions
consistent with the rest of the shell.

### Hiding Channels branding

For Channels, pass `showChannelsBranding={false}` to omit the product icon and
wordmark while keeping the switcher and navigator on the left — useful when
another surface already states product context.

To hide the branding for any product, pass `showProductBranding={false}`. The
Product layout does this, since the Product Rail already shows the active
product.

## Interactivity (props)

All handlers are optional; omitting them leaves the control inert, as before.
`*Active` props mirror `recentMentionsActive` and render the Icon Button as
toggled (Account uses a selected background and `aria-expanded`).

| Control                    | Click handler                         | Active prop             |
| -------------------------- | ------------------------------------- | ----------------------- |
| Product switcher           | `onProductSwitcherClick`              | `productSwitcherActive` |
| Back                       | `onBackClick`                         | —                       |
| Forward                    | `onForwardClick`                      | —                       |
| Search (Channels)          | `onSearchClick` (on the search input) | —                       |
| Help                       | `onHelpClick`                         | `helpActive`            |
| Recent mentions (Channels) | `onRecentMentionsClick`               | `recentMentionsActive`  |
| Saved messages (Channels)  | `onSavedMessagesClick`                | `savedMessagesActive`   |
| Settings                   | `onSettingsClick`                     | `settingsActive`        |
| Account menu               | `onAccountClick`                      | `accountActive`         |

Handlers receive the click event (`GlobalHeaderClickHandler`), so use
`event.currentTarget` as the anchor for a menu or popover your host owns —
`GlobalHeader` does not render or position menus. Handlers that take no
arguments still work. `ChannelShell` forwards these through `globalHeaderProps`,
except `onRecentMentionsClick` and `recentMentionsActive`, which stay top-level
`ChannelShell` props. Product switcher and Help also set `aria-expanded` when a
click handler is passed, so menu state is exposed to assistive technology.
Search fires on click and on Enter.

Each Icon Button receives its `aria-label` directly, so the accessible name does
not depend on the tooltip wrapper.

## Search modal

Clicking the Search field (or pressing Enter in it) is meant to open the search
modal. A large search field leads the dialog; below it sit **recent searches**
and **search modifiers** (`From:`, `In:`, `On:`) while the field is empty, and
**suggestions** (people, channels) once the user types a modifier. The footer
shows a modifier tip, then **Enter to search** once there is a query. Messages
are not searched while typing; Enter runs the search. It is one `role="listbox"`
of Compass `MenuItem` rows built on `SuggestionList`, in `Modal`.

This follows the Messages mode of the Universal Search prototype. Mode tabs (All,
Channels, Files, People, Agents) are not built yet: pass them as `headerLeading`
when they land.

<Preview caption="Search modal — click the field, then try ↑ ↓, Enter, Esc, or type from:">
  <div style={{ width: '100%' }}>
    <GlobalHeaderSearchDemo />
  </div>
</Preview>

`SearchModal` comes from `@mattermost/compass-proto`; `GlobalHeader` only needs
`onSearchClick` to open it.

```tsx
<GlobalHeader onSearchClick={() => setOpen(true)} />

<SearchModal
  open={open}
  onClose={() => setOpen(false)}
  query={query}
  onQueryChange={setQuery}
  onSubmit={runSearch}
  hints={hints}
  recent={recent}
  suggestions={suggestions}
  onRemoveRecent={removeRecent}
  onSelect={applySelection}
/>;
```

- **Host-owned:** open state, the shortcut, the query text and what choosing a
  row does (`onSelect` receives `{ kind, item }`; usually it edits `query`), plus
  portal and stacking through `overlayProps`.
- **Keyboard:** focus stays in the field. No row is highlighted until an arrow key
  is pressed, so Enter on typed text still searches (`onSubmit`). The first
  ArrowDown highlights the first row and the first ArrowUp the last. Arrows wrap,
  Enter picks the highlighted row, Escape closes, and Shift+Delete removes the
  highlighted recent search. Changing the text clears the highlight.
- **Screen readers:** the field is a `combobox` with `aria-expanded`,
  `aria-controls` and `aria-activedescendant`; groups are named by their headings.
  The hover "×" on a recent row is a pointer shortcut hidden from assistive tech;
  Shift+Delete is the keyboard equivalent.
- **Translatable:** `title`, `placeholder`, `searchLabel`, `hintsLabel`,
  `suggestionsLabel`, `recentLabel`, `listboxLabel`, `tipLabel`,
  `enterToSearchLabel` and more take strings or nodes; hint copy is a node.

## Dimensions & search field

- Header height is 40px, with tight horizontal padding on the bar and slightly
  larger inset on the left and right clusters.
- Search (Channels): fixed width 432px, height 28px, rounded container, translucent
  fill over the header; placeholder and icon use muted sidebar-type coloring.

<Divider />

## Behavior notes

- Search input is a native `type="search"` field with custom styling; focus clears
  the default outline in favor of container treatment — wire focus rings or
  command-palette behavior at the app layer if required by accessibility audit.
- Icon buttons use `padding="compact"` and `style="inverted"` for density and
  contrast on the dark header surface.
- Account uses `UserAvatar` at 24px with `status` enabled so presence reads
  consistently with the rest of the shell.
